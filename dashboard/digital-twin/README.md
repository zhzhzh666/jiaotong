# 龙岗三维交通数字沙盘

独立于 SUMO OSG 的 Three.js 三维演示。真实道路与每秒 TraCI 车辆位置配合程序化建筑、植被、路灯、道路标线、软阴影、夜景窗灯和车辆模型。界面提供无雨/暴雨/治理三种情景、时间轴、播放倍速、自动运镜、全域鸟瞰、街区和车辆跟随、点击车辆查看速度、建筑/积水开关与全屏。

## 启动

在项目根目录双击 `启动三维仿真.cmd`，或运行：

```powershell
.conda-env/python.exe scripts/serve_digital_twin.py
```

默认地址为 http://127.0.0.1:8766/ ，只监听本机。Three.js r170 与 OrbitControls 已随代码保存，不依赖外部 CDN、字体、地图密钥或网络。服务器自动发送已有 gzip 数据以减少加载量。按空格播放/暂停；拖动旋转、滚轮缩放、右键平移；点击车辆检查速度。面板到达/在途统计来自每分钟交通账本，车速为当前轨迹样本均值。

## 数据与重建

本机 `data/` 已生成完整数据；大型 JSON/gzip 不入 Git。新机器须先复制原 SUMO 实验及其原始输入，并使用本项目独立 Python 环境运行：

```powershell
.conda-env/python.exe scripts/export_digital_twin.py
.conda-env/python.exe scripts/audit_digital_twin.py
```

导出器在新的 `data/processed/digital_twin_replay_<UTC时间>/` 重放冻结控制器，保留全部 replay 输出；不会覆盖历史实验。每秒读取订阅，补充刚出发车辆的直接查询，保存全部可见车辆，不抽样删车。连续帧间进行位置与方向插值；情景切换保持同一时刻。数据和回放来源均记录在 JSON 中。

独立核验详见 `docs/validation/digital_twin/data_audit.json`。三情景各 14,401 帧，逐秒车辆数与原 SUMO summary 一致；全部 720 行分钟统计与历史 CSV 一致；4,969 条道路形状、源弧顺序与积水数组经过核对。

## 解释边界

- 来源：`20261118T175153_sumo_492a503a`；3 km × 3 km、5% 合成需求、3,588 辆计划。到达 3,588/877/1,230 辆。
- 建筑、树木、路灯、材质和光照均是程序化视觉配景。未接入真实建筑轮廓/高度、实测高程或城市实景模型。
- 道路为原实验的推定平面道路；节点是优先通行路口，未虚构信号控制。
- 蓝色积水带只代表相应源有向弧的模型水深，橙色横线代表达到 0.30 m 中断阈值；不是连续二维水面或真实水动力。
- 模型未经实测校准，原试验在途改道次数为 0。页面是已计算 SUMO 试验的离线轨迹回放，不是在线 TraCI 控制器。
- 每秒线性插值仍可能在急转弯处有亚秒级位置近似；统计以原始账本为准。0—59 秒没有分钟账本时显示“—”。
