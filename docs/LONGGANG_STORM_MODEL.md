# 龙岗暴雨内涝情景建模步骤

本模块面向龙岗区不含大鹏的交通仿真实验，提供合成降雨、道路网格积水代理、水深时序与道路关联。采用独立蓄水桶模型，不解析排水管网和水流传播，也不是已验证的历史内涝重建。当前运行目录见`configs/active_research.yaml`的`accepted_synthetic_storm`，参数入口是`configs/longgang_storm.yaml`。

## 与方案A B C的关系

本次不严格对应用户所列三类，更接近A的参数化扩展：**合成道路低点＋合成降雨驱动的动态积水假设**。没有采用已核实的历史积水点。使用DSM帮助选择代理低点，并不等于实施了B的地表汇流计算。

| 方案 | 关键区别 | 本次情况 |
|---|---|---|
| A 历史积水点加动态水深假设 | 需要可信历史点位 | 动态水深思路接近，但位置由道路与DSM合成 |
| B DEM加历史降雨及简化地表汇流 | 计算地形控制的水流转移 | 未实现相邻单元汇流，且降雨为假设，不称B |
| C SWMM与二维水动力耦合 | 需要管网及地表水动力过程 | 未建立管网或二维水流模型，不称C |

这是一套用于交通韧性压力实验的合成输入。若升级B，需取得事件降雨并新增地形水文处理、汇流与水交换计算；若升级C，还需可用管网和更完整的率定资料。

## 第一步 固定研究范围与已有数据

沿用已验收龙岗OD包的研究边界及推定有向图。龙岗主面约386.96 km²，不含大鹏；所供边界的坐标基准按供应方声明使用WGS84，尚未独立核准。距离、分区和道路采样使用EPSG32650。

输入包括本地深圳OSM机动车线几何、Copernicus GLO-30 DSM东经114°瓦片，以及已冻结龙岗OD包。先核对OD包中边界、图、配置及源路网SHA，避免误用南山数据或错配道路ID。

DSM是包含建筑和植被的地表模型，垂直基准为EGM2008；它不是裸土地形或排水沟渠测量。将DSM按龙岗边界原生像元中心裁剪，输出`gis/longgang_dsm_30m.tif`，不插值生成更精细地形。道路点和局部地形统计从原始DSM读取，边界附近允许使用区外邻域地形。

已有13个龙岗标签一致水位站和1个行政标签冲突站仅作为接收资料背景。SW路面零点与地址代理位置未核实，本次不把它们当作实测路面积水深度，也未用于拟合参数。没有取得本地可用管网、管径、泵站或事件级实测雨量。

## 第二步 建立道路积水代理单元

从与研究边界相交的源道路中，沿用OD模型的通行权限、单行及道路类型筛选规则，保留源文件行位置`source_feature_position`。这些位置用于和既有GraphML准确对应，不假定OSM way ID天然唯一。

道路分层按源标签处理：桥梁、隧道和非零layer不套用地面积水，标为未建模。标签缺失按地面处理也是一项假设，真实立交漏标仍可能造成错误。对其余地面道路裁剪至研究边界后，以不超过100 m的间距采样，含两端点；按UTM坐标划入250 m网格。在每个有有效地形值的道路网格内，取采样点中DSM最低者作为代理单元的位置。

选择低点是构造压力情景的规则，不能把这些位置称为历史积水点或已识别的真实洼地。每个单元并不意味着整块250 m网格被淹，也没有实测积水面积。未覆盖道路的地区不在本模型空间表达范围。

结果保存在`gis/flood_proxy_sites.geojson`和`raw/road_sample_coverage.parquet`；后者保留逐采样点位置、地形有效性及所属单元。道路状态和覆盖信息分别在`raw/road_feature_status.csv`与`raw/site_road_links.csv`。

## 第三步 构造四档暴雨过程

模拟窗口为24小时，15分钟步长，共96个降雨区间、97个水深端点。四档参考总雨量为0、100、200、300 mm，对应normal、general、severe、extreme。这些是压力实验档位，不是深圳暴雨等级或经IDF标定的重现期。

假设降雨发生在第5至13小时，用两个高斯峰形组合。对第k个区间中心时刻tₖ：

**wₖ=0.7 exp[−0.5((tₖ−8)/0.65)²]+0.3 exp[−0.5((tₖ−10)/1.0)²]。**

在5≤tₖ<13之外令wₖ=0，再归一化使Σwₖ=1。情景参考区间雨量Rₖ=P总wₖ，单位mm/区间；雨强为Rₖ/0.25，单位mm/h。总量不能直接当作小时雨强。

采用seed=42、64个随机傅里叶模态构造空间平滑高斯随机场，相关长度参数1,500 m，对数标准差0.15。点乘数gᵢ=exp(0.15Zᵢ)除以各代理单元乘数的算术均值。点雨量为Rₖgᵢ，四档情景共用同一空间形状。归一化保证的是道路代理单元平均雨量，不是龙岗全区面积平均雨量；该随机场是合成近似，不是雷达雨场。

输出`raw/reference_rainfall.csv`和`raw/site_parameters.csv`。后者保存每点乘数与全部蓄水参数。

## 第四步 设置径流与排水参数

设道路代理点的DSM高程为zᵢ，以点附近±10个原始像元（21×21窗口，约600 m范围）有效DSM中位数为mᵢ，定义相对低地代理分数：

**sᵢ=clip[(mᵢ−zᵢ)/10,0,1]。**

建筑和植被会影响这个分数，不能把它当作真实汇流分析。使用以下未标定参数：

| 参数 | 设定 | 解释 |
|---|---|---|
| 径流系数C | 0.8 | 统一假设，未区分实际土地利用 |
| 假设汇水/积水面积比αᵢ | 2+2.5sᵢ | 2至4.5，假设低点承受更多集中径流 |
| 常量排水能力cᵢ | 8+10(1−sᵢ) mm/h | 8至18，假设低点排水更弱 |
| 线性退水时间常数τ | 4 h | 额外随储量增加的排水项 |
| 初始水深 | 0 m | 干燥初始条件，无前期积水 |

α没有来自真实汇水区面积。因缺少积水面积及水交换关系，本次只核算假想单元上以mm计的等效水量，不能将各单元简单求和解释为真实流域总水量。

## 第五步 逐时计算积水形成与退水

单元储量H以mm计，时间步长Δt=0.25 h。每个区间按下面顺序计算：

1. 有效集中径流输入：**Iₖᵢ=RₖgᵢCαᵢ**，单位mm。
2. 排水量：**Dₖᵢ=min(Hₖᵢ+Iₖᵢ,cᵢΔt+HₖᵢΔt/τ)**，单位mm。
3. 下一时刻储量：**Hₖ₊₁,ᵢ=Hₖᵢ+Iₖᵢ−Dₖᵢ**。
4. 输出水深：**hₖᵢ=Hₖᵢ/1000**，单位m。

排水不能超过可用水量，因而水深非负。13小时雨停后输入为零，得到：

**Hₖ₊₁=max[(1−Δt/τ)Hₖ−cΔt,0]。**

这是显式离散模型，要求Δt≤τ；τ不是实际退水所需时长。各单元相互独立，不传播洪水，也不描述管网、河流水位、潮汐顶托、下穿隧道灌水或雨水口堵塞。

`raw/site_depths/{case}__{scenario}.parquet`存端点水深，`raw/balance/`保存每个区间的雨量、输入、排水和储量变化，逐步核算ΔH−I+D。

## 第六步 关联道路并与OD路网对接

同一源道路要素可能经过多个代理单元。每个时刻取与该道路有效采样点相连单元的最大水深，作为该源线的合成暴露值。该最大值法偏保守，较长的源线会把局部积水影响传播到该源线的其他段；不应解释为整条道路实际等深淹没。100 m道路采样和250 m代理格也可能漏掉小尺度积水。

桥隧、非零layer及完全缺失地形覆盖的道路水深为NaN，保持“未知”，不能当成0或安全。部分地形覆盖时给出部分覆盖标记。本次并不计算这些未知道路的通行能力。

从既有GraphML流式读取真实保存的edge_id、u/v/key、源行位置和段号，筛出与龙岗边界相交的段，输出`raw/od_graph_arc_mapping.csv`。ID与龙岗OD图一致，但该图本身仍为几何推定、尚未认证。跨边界段可能包含区外部分，映射中有单独标记。

完整道路端点矩阵保存在`raw/road_depths/{case}__{scenario}.npz`。必须用其中`source_feature_positions`排列对应列，`time_h`对应行，并用`modelled_features`区分未知值。基准四档另提供Parquet长表。

接入后续交通模型时，以映射表的`source_feature_position`连接水深，再用原样保存的u/v/key连接OD图；不能用字符串猜节点或套用南山ID。96个交通区间可取97端点中前96个起点状态，并明确按起点保持；峰值位于区间内时这一近似可能低估影响。当前仅提供水深输入，没有运行速度/容量退化、封路、交通分配或韧性计算。0.30 m在本次表中仅为统计阈值，不等同于已实施封路。

## 第七步 统计持续时间与恢复

分别统计水深严格大于0.01、0.15、0.30、0.40 m的时长，端点之间按线性插值计算穿越时刻。道路暴露汇总表另提供“大于等于0.30 m”的同时道路要素数，比较符号应按字段含义使用。

恢复采用0.01 m分析阈值，定义为事件峰值后最后一次下降穿越阈值，且至24小时不再超阈值。状态分为从未超过、窗口内恢复、24小时仍超过（右删失）。从未超过和未恢复单元都不填写恢复时刻。1 cm是分析定义，不是安全行车标准。

输出`raw/site_threshold_metrics.csv`、`raw/baseline_road_threshold_metrics.csv`与`raw/scenario_summary.csv`。道路要素数不是道路条数、面积或整个有向路网比例。

## 第八步 参数敏感性与数值核验

共比较五组参数：基准、常量排水能力0.5倍、1.5倍，以及退水时间常数2 h、8 h。一次只改变一项，不能把这些变化直接称作排水工程效果。四档降雨共形成20组完整过程。

基准另把每个15分钟区间雨量均分到三个5分钟区间重新积分，比较共同端点的水深，输出`raw/time_step_check.csv`。这只检查离散时间敏感性，并未增加真实雨量的时间信息，也不能证明模型已水文校准。

自动核验包括雨量总量、单位、水深有限非负、正常情景全干、雨停后单调退水、降雨/排水/退水敏感性顺序、单区间与全事件水量平衡、右删失与未知道路处理。独立审计回读全部20组水深与水量账本，复核公式、离散无雨闭式解、道路最大值聚合、SHA与ZIP内容。具体数值见阶段报告及`docs/validation/longgang_storm/numerical_audit.json`。
