# 龙岗 ERA5 驱动的 B 方案：步骤与计算方法

用户选择第二个降雨来源ERA5/Open-Meteo后，已完成B方案研究原型：ERA5逐小时降雨＋DSM地形＋固定D8蓄泄树。相较旧独立道路蓄水桶，水会沿地形连接从上游网格传到下游；仍不是SWMM管网或二维浅水方程模型。数值运行通过不代表实测校准。

## 1. 获取并固定降雨

通过[Open-Meteo历史接口](https://open-meteo.com/en/docs/historical-weather-api)，固定`models=era5`、`cell_selection=nearest`和`timezone=Asia/Shanghai`，一次请求9个不同的0.25°网格（纬度22.5/22.75/23.0，经度114.0/114.25/114.5）。记录请求URL、HTTP响应原字节、返回网格中心、时间、许可与SHA。禁止把重复请求同一网格解释为独立雨量站。

模拟时窗为北京时间2023-09-06 00:00至09-11 00:00。ERA5标记时刻t的量属于(t−1小时,t]，因此取9月6日01:00至11日00:00共120条/网格，恰好覆盖120小时。请求额外覆盖9月11日用于取得00:00的末小时。1,080条无缺值，全部非负，单位mm。先前72条单网格样例不直接替代完整时窗。

雨量按原始ERA5网格在空间上分片常数赋值，不通过精细插值制造空间信息。区内平均量按150 m网格与行政区实际相交面积加权，4个ERA5网格参与龙岗平均；主5 km计算域共用6个，扩大域可使用其余网格。

数据署名：[Weather data by Open-Meteo.com](https://open-meteo.com/)，Copernicus Climate Change Service/ECMWF ERA5；API数据按[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)署名与说明变更，服务使用还需遵守[提供方条件](https://open-meteo.com/en/licence)。ERA5为约25 km、逐小时再分析估计，不能称为龙岗站点实测。

## 2. 准备地形与范围

复用冻结OD包中龙岗不含大鹏边界。在EPSG:32650下将边界向外扩5 km，以其外包矩形作为计算域；10 km扩大域用于边界敏感性。行政边界不是排水分界，本轮尚未认证整个上游汇水区。

拼接已有Copernicus约30 m DSM的E113/E114两块，以面积平均重采样为150 m网格。主域239×280共66,920格，所有格必须有有限高程；保留原始高程。DSM包含建筑与植被，150 m不能表达路缘、雨水口、下穿通道或像元内部分淹没；所得深度只适合作区域尺度参数探索。

每格面积A=150²=22,500 m²；报告区内面积按与龙岗边界的实际相交比例计，合计386.957601 km²。外围格允许向计算域外排出，外来流入设零，无河道/潮汐顶托。

## 3. 建立地形汇流连接和储量

从矩形边缘格开始，以高程为优先级向内遍历8邻格（priority-flood）。每个内部格连接到已出队的父格，父格排序严格更早，形成无环D8树；这不是按水头动态求解的二维流向。

算法给出可排向边缘的填洼高程F_i，但不覆盖原高程z_i。每格储量阈值为d_i=max(F_i−z_i,0)。在深度超过d_i后，超出部分参与下游转移；阈值以内仍可因损失项退水。此方法用逐格阈值近似洼地蓄量，未构造整个连通洼地的统一水面及容积曲线。最大阈值约29.38 m可能含DSM伪洼地，不能视为实测洼地深度。

停留时间使用假设关系：

\[
v_i=v_0\sqrt{\max(s_i,s_{min})/s_0},\qquad
\tau_i=\mathrm{clip}(L_i/v_i,900,21600)\ \mathrm{s}.
\]

L_i为相邻格距离，s_i为填洼高程向父格的坡度。v_0=0.04 m/s，s_0=0.01，s_min=0.0001；参数见配置。这里v_i是用于停留时间的假设尺度，不是实测流速或Manning水动力计算。

## 4. 计算降雨、损失、蓄水和网格间传递

内部步长Δt=180 s，15分钟保存一次，共481个端点。初始表层深度h_i=0。每小时降水在小时内均匀分配，转为步内深度R_i=P_i(mm)×Δt/3600/1000；没有获得真实3分钟或15分钟降雨峰形。

每步按下列顺序计算，所有内部格同时向下游转移，接收的水从下一步起继续下传：

\[
\tilde h_i=h_i+R_i,\quad
\ell_i=\min(\tilde h_i,c\Delta t/3600/1000),\quad
q_i=\max(\tilde h_i-\ell_i-d_i,0)(1-e^{-\Delta t/\tau_i}).
\]

\[
h_i^{new}=\tilde h_i-\ell_i-q_i+\sum_{j:\,receiver(j)=i}q_j.
\]

基准c=4 mm/h，将入渗与未解析排水合并为容量损失；只有现存水可被扣除，不会产生负水深。该损失并非真实管网能力。边缘出口q_i计入边界排出；所有深度乘A变成m³后逐步记账：降雨−损失−边界排出=储量变化。不能把全计算域水量冒称区内水量平衡，因为区内有边界间流动。

## 5. 映射到道路并做敏感性

复用既有冻结包的33,597个地面道路采样位置和源要素编号；映射至8,530个150 m网格。每条源线取其有效采样网格的最大估计深度。6,848条地面源线建模，952条桥隧/非零layer等保持NaN，不能填成干燥零值；原86,807条推定OD图有向弧映射保留，不重建或猜测ID。

八组计算：无雨对照、ERA5基准、雨量0.7/1.3倍、损失能力0.5/2倍、停留时间0.5/2倍。除基准ERA5数据外，倍率均为假设敏感性，不对应官方重现期。道路最大值按15分钟端点统计；网格峰值与曾超阈面积还使用内部步。阈值0.15/0.30 m仅用于暴露统计，本轮不据此自动封路。

## 6. 核验、结果与下一步

执行151项现有及新增测试、依赖检查、基准60 s复算、10 km扩大域复算、独立原始降雨/水量/网格/道路/SHA/ZIP审计。三张PNG逐一查看，SVG同时保留。数值细节及结果见[阶段报告](PHASE_LONGGANG_ERA5_SURFACE_REPORT.md)，原始证据见`docs/validation/longgang_era5_surface/`。

区内ERA5累计约180.10 mm，基准道路样点最大估计深度1.0309 m。损失能力改成2/8 mm/h时为4.0988/0.0113 m，说明绝对水深受未标定假设支配。输出可用于方法和敏感性实验，不能声称重建了真实2023年内涝。优先补齐站点降雨、实测积水、裸地DTM、土地覆盖及排水约束，再标定验证；本轮没有更新交通分配、韧性或SUMO。

## 重现步骤

从项目根目录，使用独立环境：

```powershell
.\.conda-env\python.exe scripts/acquire_longgang_era5.py
.\.conda-env\python.exe scripts/run_longgang_era5_surface.py --rainfall data/raw/longgang_era5/20261118T132916_era5_184f075b
.\.conda-env\python.exe scripts/audit_longgang_era5_surface.py data/processed/longgang_era5_surface/20261118T133312_era5_surface_d4aecd75
.\.conda-env\python.exe -m pytest -q
.\.conda-env\python.exe -m pip check
```

重新获取/运行会创建新run_id，后两步应替换为实际新目录。复用已冻结降雨包则无需再次联网。完整栅格/数组/ZIP留本机，GitHub存源码、配置、方法、精简原始降雨及审核证据。旧合成包和manifest保持不动。
