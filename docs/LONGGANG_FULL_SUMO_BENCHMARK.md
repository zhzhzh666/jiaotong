# 全龙岗5%需求：SUMO基准试跑与耗时预算

本阶段按用户要求，先运行一次完整龙岗（不含大鹏）的无雨基准，关闭3D窗口，记录每个仿真小时的耗时、Python与SUMO合计内存，再对后续五组比较及迭代分配做预算。当前不把迭代分配预测写成已运行的DUE结果。

## 1. 覆盖范围与需求口径

读取既有合成OD包中的龙岗边界。对冻结源图的每条线段进行投影空间相交判断，保留全部与龙岗相交的有效弧、边界外3 km缓冲区内相交弧；再补入本次抽中车辆在完整源图上的整段正常路径。

源图中自环或长度不超过0.1 m的退化弧不参与SUMO转换，其数量单独报告。缓冲区内的其他行政区道路仅作为连接道路，不扩展研究行政区范围。新替代路径仍受“缓冲区＋抽中正常路径并集”外边界限制；此模型没有全深圳其他车辆背景流，也没有外部—外部过境OD。

与先前3 km×3 km试验不同，本次先在完整483×483矩阵上抽取车辆，再保留整段行程，**不按出入片区次数拆成多个车辆访问**。全区道路覆盖也不意味着全需求加载：车辆数量仍是5%的物理缩放需求，不能将输出乘20解释为100%需求结果。

## 2. 抽取车辆及保持不可达账本

固定seed=42。每个15分钟区间，对于全部分区对：

$$N_{ij,k}\sim\operatorname{Poisson}(0.05\times q_{ij,k}\times0.25).$$

其中$q$为既有合成OD的veh/h；区间内发车时刻均匀抽样。即使区内出行、连接点缺失或源图不连通，该次抽样也保留，并记录未加载原因。

先在完整冻结源图的走廊图上计算抽中分区对的正常最短路径，再展开回源有向弧。SUMO转向不一致时，只在相同首末弧之间寻找可行路径；若失败仍保留为无效计划，不能伪造连接。所有有效计划的首弧起点及末弧终点均须对应原OD连接点。

## 3. 时窗与交通设置

- 北京时间2023-09-10 10:00—14:00，固定与此前片区试验相同时窗；本次不按全区收益重新选窗。
- 前3小时按计划出发，最后1小时继续处理已有计划；空网络起步，不继承此前排队。
- 1秒微观仿真、60秒发车尝试/输出、300秒更新当前旅行时间成本；无雨基准不做在途改道。
- 车辆出发时按当时成本选路；拥堵车速观测以EMA系数0.5更新，速度下限0.5 m/s。
- 维持既有单有效车道/方向、优先权交叉口、容量tau代理；未经实测车道、信号、需求或跟驰标定。
- 关闭自动传送；未完成车辆留在账本，不能删除后计作到达。

为了控制全区计算开销，无雨时不重复向每条边写入相同限速及通行权限；tau按道路状态预计算；累计到期需求用排序查找。湿情景仅对改变的道路发送限速/权限更新。上述改动不会令无雨基准变成迭代均衡分配。

## 4. 耗时与内存测量

后台线程每1秒记录一次：

| 字段 | 含义 |
| --- | --- |
| `python_rss_mib` | Python主进程驻留工作集 |
| `children_rss_mib` | 当前子进程驻留工作集合计，主要是netconvert或SUMO |
| `combined_rss_mib` | 两者之和；共享页可能重复计算，不是独占物理内存 |
| `host_available_mib` | 整机可用内存，受其他应用影响 |
| `wall_s` | 从该次监测开始的真实秒数 |

每完成3600仿真秒，立即刷新`cases/dry/hourly_performance.csv`，保存该仿真小时耗时、累计耗时、车辆状态和采样内存峰值。首小时包含控制器初始化；网络准备与SUMO启动另行记录。1秒采样可能漏掉更短的瞬间内存峰值。

`preparation.json`记录需求抽样、路径、空间筛选、网络转换和输入封存的总耗时及netconvert子项。`result.json`的`wall_seconds`包括控制循环及结束输出/关闭，但不含SUMO启动；`resources_summary.json`记录本次从准备至运行结束的总耗时及总体采样峰值。

## 5. 一次基准能够支持怎样的预算

只有无雨全区案例是本轮完整交通试跑。另做无车辆控制写入/路径查询微基准，以及基于无雨时变边成本的一次完整`duarouter`路径刷新，测量后续额外工作的量级。

记准备耗时为$P$，已准备网络的无雨单次耗时为$B$，其中计时测得的在线出发路径查询为$Q$，一次离线完整路径刷新为$R$。标准预先分配路线的迭代不需要再为每辆出发车在线查路，因此先扣除$Q$，避免重复计入选路。迭代$N$轮的基础预算为：

$$T_N\approx P+N(B-Q+R).$$

同时列出每轮剩余交通计算耗时变为$2(B-Q)$的预留预算。未单独实测预分配固定路线运行，该剩余量仍是条件估算；未测Gawron替代路径概率更新的额外开销，也不能保证第10、20、30或50轮收敛。稀疏观测边成本中没有相应区间的道路由duarouter回退至正常自由流成本。

五组预算以$P+5B$为基础，加上四个湿情景的道路控制写入估计及两个滚动组的额外查询估计。常规估计借用无雨组活跃车辆检查数；保守规划项假定所有有效车辆在全部滚动时点均活跃，并预留两倍无雨交通运行时间。此范围不是统计置信区间，也不保证涵盖真实湿情景耗时。

**一组基准不能测出另外四组的准确运行时间，也不能确定均衡收敛需要几轮。** 报告明确区分实测值、条件外推与尚未测量的部分。

## 6. 运行与核验步骤

在项目根目录使用独立环境：

```powershell
# 无GUI全区5%无雨基准；每次建立新run_id
.\.conda-env\python.exe scripts/run_longgang_full_benchmark.py

# 对实际输出目录执行车辆、路径、耗时和内存核验
.\.conda-env\python.exe scripts/audit_longgang_full_benchmark.py data/processed/longgang_sumo_full/<run_id>

# 测量控制/路径刷新并生成条件预算
.\.conda-env\python.exe scripts/budget_longgang_full_benchmark.py data/processed/longgang_sumo_full/<run_id>
```

输入、源码和配置以SHA256封存，保留失败记录和完整本机数据；不改写先前片区包。核验包括全部源边ID、有效计划的转向连接及OD端点、实际注入路线、所有车辆去向、逐秒占用积分重放，以及小时耗时和内存轨迹重算。
