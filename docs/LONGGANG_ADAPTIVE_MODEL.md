# 龙岗分区积水、点队列交通与多目标治理：计算步骤

本阶段按用户确认的路线接入ESA WorldCover分区损失、分道路退化、跨时段点队列和NSGA-II。用户同意先使用相对成本、最多治理3处。当前是4处候选的可穷举研究实验，未经实测标定；不代表全区工程最优方案、完整OD精确加载或动态用户均衡。

## 1. 固定范围和数据

龙岗不含大鹏，复用此前386.957601 km²边界、66,920个150 m地形网格、ERA5的120个完整小时及483×483合成OD。原始包、失败下载、旧源码与manifest保留。气象时窗为北京时间2023-09-06 00:00至09-11 00:00；数据仍为再分析，而非站点实测。

新增[ESA WorldCover 2021 v200](https://doi.org/10.5281/zenodo.7254221)，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，署名ESA WorldCover consortium与Copernicus Sentinel。N21E111、N21E114两瓦片通过逐段校验的HTTP范围读取，归档未重采样的原生分类裁剪；裁剪GeoTIFF经过无损重编码，不能声称其文件字节等于完整远端瓦片。另存不完整块缓存，文件名明确标记INCOMPLETE，不能作为完整数据使用。

原10 m分类先以最近邻采样至30 m，再以每个150 m网格的5×5分类计算覆盖比例。这是近似覆盖比例，未做精确10 m面积交叠。全域分类必须完整，不能静默将缺测填为建成区。

## 2. 用土地覆盖设置空间损失，并重算治理后的积水

每格综合损失能力取覆盖比例加权：建成区2、植被8、裸地4、水体0 mm/h。它合并入渗与未解析排水，全部是参数假设；土地覆盖是真实公开分类，不等于取得真实排水能力。

\[
c_i=2f_{built,i}+8f_{vegetation,i}+4f_{bare,i}+0f_{water,i}.
\]

保持已冻结的priority-flood D8连接、原DSM洼地储量阈值、线性蓄泄停留时间。内部180 s，输出900 s，按“加雨→容量受限损失→同时下传”更新。以全域降雨−损失−边界排出=储量变化核对水量。

先计算无治理的0.7/1.0/1.3倍ERA5降雨。按1.0倍情景中地面道路采样格峰值×道路采样关联数量平方根排序，选取彼此至少2 km的4个位置。候选筛选只看积水暴露，不使用随后优化的交通收益。

每处治理假设在半径750 m、与龙岗相交的网格增加4 mm/h损失能力，行政区边缘按区内比例缩放。多处重叠取并集，不重复叠加效果。每个组合、每档雨量都重新执行蓄泄计算，不能直接改小道路水深或提高道路容量来替代排水计算。圆形作用范围并非真实管网汇水区；新增能力、空间作用范围和相对成本待实测或工程资料替换。

## 3. 道路退化及保留有向路网

原推定深圳有向MultiDiGraph用于跨区路径；源道路弧ID及平行边保留。将无分叉、非OD连接点的连续弧收缩为有向走廊，保存每条走廊的完整原弧序列。最短路径保持正权下的方向连接；串联走廊用时间之和、最小容量近似，内部排队位置未逐弧解析。

水深映射复用6,848条地面源线有效采样网格的最大值；952条桥隧等仍为NaN。仅按冻结的86,807条区内/跨界弧ID应用这些源线水深，逐一校对u/v/key；同一源线在区外的其他弧不继承区内水深。交通评估对未知及积水覆盖外道路采用**假设正常**情景，不把NaN改写成观测无积水。早期试算因区外弧适用范围错误已终止并保留，仅对配置、数据SHA及水文计算AST一致的积水缓存复用，交通和路径库全部重建。

采用Pregnolato等2017的水深—速度关系（[DOI](https://doi.org/10.1016/j.trd.2017.06.020)，项目留存PDF第7页Eq.4）：水深w以mm计，限速为0.0009w²−0.5529w+86.9448 km/h；取不超过正常道路速度，h=0保持原速。h≥0.30 m封路，容量归零。

容量采用C=C0 max(0.20,1−a h/0.30)，其中a按高速/快速主干/主干/次干/支路/其他分别为0.65/0.70/0.75/0.80/0.85/0.90。C0使用配置的道路等级容量，假设每方向一条有效车道，未取得实测车道与饱和流量。容量关系、道路分类参数及封路阈值均为本项目假设，不能归于Pregnolato论文或官方标准。

## 4. OD分层抽样与跨时段点队列

完整OD仍用于总需求记账。对连接有效的每个起点，按目的地概率累计分布做2个系统分层抽样，权重使每个起点、每个时段的总量精确保持。重复抽中目的地合并。此法保持起点总量，但目的地分布、路径流量是抽样近似；另做4层抽样检查敏感性。

区内需求和未接入路网需求分别保留。当前合成三时段矩阵成比例；代码会拒绝不满足此前提的新矩阵。将同一合成24小时需求重复5天，不声称它是2023年真实逐日需求。

路径库由无雨、1.0倍各道路各自峰值、1.3倍各道路各自峰值状态的最短路径组成。峰值状态只用于生成替代路径，不视为同一时刻的洪水图。每15分钟，新增需求及起点等待需求在当前可通行的库内路径中，按“行驶时间＋当前排队量/通行能力”选择最小成本路线；没有可用路径时继续在起点等待，不删除需求。

内部交通步长60 s。车辆先经历向上取整的走廊行驶时延，再进入出口点队列；到达下条道路后继续经历行驶时延。每条走廊每步服务上限为CΔt/3600，按各路径商品的队列占比分配。下一走廊关闭时，相应商品留在上游点队列。关闭期间排队保持，恢复后继续放行。

这是**按路径商品比例服务的流体点队列动态加载**：有车辆跨时段传递，允许出发时绕行；不保证严格FIFO，没有物理排队回溢、信号或交叉口冲突，也没有行途中重新规划及动态均衡迭代。拥堵由队列服务体现，未再次叠加BPR，以免重复计算。每步核对容量，逐步核对“累计释放=累计完成＋行驶中＋道路排队＋起点等待”。另做30 s时间步检查；步长误差和抽样差异必须随结果披露。

## 5. 目标函数和NSGA-II

用户确认最多选3处，相对成本为治理区内面积km²×1成本单位/km²，与真实人民币造价无关。二进制mask表示选址，三个目标均最小化：

1. 三档雨量中相对同一抽样、同一时间步无雨参考的最大**广义成本增量**；
2. 三档雨量中时窗末最大未完成车次，包含未接入需求；
3. 相对治理成本。

广义成本以有限时窗内网络占用时间积分，加未完成车次×2小时终端惩罚，再加未接入车次×2小时、区内车次×300 s组成。惩罚是研究假设，不代表未完成车辆实际在2小时后到达。它不是仅对已到达车辆计算的平均延误，也不能把惩罚后的指标当作真实行程时间。

NSGA-II使用二进制交叉、逐位变异、超出3处时修复、非支配排序、拥挤距离锦标赛与精英保留；3个随机种子。算法出处：[Deb等2002](https://doi.org/10.1109/4235.996017)。随后独立穷举4处候选的全部15个可行组合，重构精确Pareto集并核对NSGA-II覆盖率。精确最优性仅限这4处候选与当前假设。

推荐组合采用精确Pareto集中三个目标归一化后到理想点的等权距离和最小者。该选择规则不是官方偏好或唯一最优答案，完整非支配集同时交付。

## 6. 核验和重现

新增单元测试覆盖空间损失水量、道路关闭与未知值、起点总量、共享容量、道路恢复、可解析排队、平行道路替代路径及NSGA-II可行性。完整测试与pip check执行后留存记录。独立审计使用scatter-add重放基准及推荐组合水量/道路值，重构分层权重、源弧划分、有向路径连续性、车辆账本和暴力Pareto比较。
