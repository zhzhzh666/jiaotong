# 暴雨内涝下城市交通网络韧性评估与优化——完整项目开发任务书

## 1. 项目目标

开发一个基于真实深圳城市道路网络的暴雨内涝交通韧性评估与优化仿真系统。

系统需要实现：

- 真实城市道路网络获取与拓扑建模。
- 历史积水点与道路空间关联。
- 城市交通需求及OD矩阵构建。
- 暴雨内涝时空变化模拟。
- 积水条件下道路速度与容量退化。
- 基于用户均衡的交通流重新分配。
- 结构韧性、性能韧性及功能韧性评价。
- 关键积水道路识别。
- 有限治理预算下的道路防涝治理优化。
- SUMO微观交通仿真。
- 多种治理策略对比实验。
- GIS地图及交互式数据可视化。

初期以深圳市南山区作为真实实验区域，使用Sioux Falls标准路网进行算法正确性验证，系统架构应支持后续扩展至深圳全市。

# Phase 03：交通小区划分与OD需求矩阵构建

## 任务

将研究区域划分为交通分析小区，即TAZ。

初期使用500米或1000米规则网格，后续可以根据行政区域和土地利用类型优化交通小区。

根据人口、住宅、就业设施、商业设施等信息估算交通产生量及吸引量。

如果能够获取真实OD数据，优先使用真实数据。

如果无法获得，使用重力模型构建合成OD：

`q_ij = A_i × B_j × O_i × D_j × f(t_ij)`

其中：

- O_i为交通小区产生量。
- D_j为交通小区吸引量。
- t_ij为正常道路网络出行时间。
- f(t_ij)为距离或时间阻抗函数。
- A_i、B_j为平衡系数。

使用IPF/Furness方法使OD矩阵满足设定的产生量和吸引量。

考虑研究区域边界的车辆流入及流出需求。

至少构建：

- 平峰交通需求。
- 早高峰交通需求。
- 晚高峰交通需求。

不同暴雨治理策略必须使用相同的OD需求，确保公平比较。

统一交通流量单位为veh/h，道路容量单位为veh/h，道路时间单位为秒。

## 输出

- traffic_zones.geojson
- zone_population.csv
- zone_connectors.csv
- od_matrix.csv
- od_peak.csv
- od_offpeak.csv
- od_heatmap.png
- od_desire_lines.png

## 验收条件

OD矩阵非负，产生量与吸引量符合设定，随机抽取OD对能够正确连接至道路网络。

报告OD矩阵是真实数据还是合成数据。

# Phase 04：动态暴雨内涝情景建模

## 任务

建立能够描述积水增长、峰值和自然消退的时间序列模型。

基础仿真窗口设置为24小时，时间间隔15分钟，可通过配置文件调整。

为每条受影响道路生成积水深度时间序列：

`h_e(t) = H_e × g_e(t)`

其中H_e为该道路峰值积水深度，g_e(t)为归一化的积水变化函数。

构建：

- 正常无灾害情景。
- 一般内涝情景。
- 严重内涝情景。
- 极端内涝情景。

考虑以下空间差异：

- 历史积水点位置。
- 低洼地形。
- 不同道路的峰值积水深度。
- 不同区域积水时间延迟。
- 不同道路的排水恢复能力。
- 相邻积水点之间的空间相关性。

如果没有真实水动力模型及标定数据，明确将该模块称为参数化内涝情景模拟，而不是精确水动力预测。

## 输出

- flood_scenarios.yaml
- flood_depth_timeseries.parquet
- flood_depth_maps/
- flood_animation.gif
- flood_depth_curves.png

## 验收条件

积水深度非负，符合设定的增长与消退过程。

正常情景积水深度为0。不同暴雨强度和空间分布能够产生可区分的积水情景。

# Phase 05：道路交通性能退化模型

## 任务

实现积水深度对道路自由流速度与通行容量的影响。

首先尝试根据已核实的Pregnolato等人的论文公式实现积水深度—速度模型。

另外实现一个可配置的简化模型作为对照：

`v_e(t) = v_e0 × max(0, 1 - h_e(t)/h_critical)^gamma`

`c_e(t) = c_e0 × max(0, 1 - h_e(t)/h_critical)^eta`

初期将30厘米设置为普通机动车道路中断的仿真假设阈值，并开展阈值敏感性实验。

不得将该阈值作为真实车辆涉水安全建议。

道路封闭时，直接禁止车辆进入，不应通过容量为0的BPR函数计算通行时间。

定义四种道路状态：

- 正常通行。
- 轻度退化。
- 严重退化。
- 完全中断。

## 输出

- road_disruption.py
- dynamic_road_state.parquet
- depth_speed_curve.png
- depth_capacity_curve.png
- road_disruption_map.png

## 验收条件

无积水时速度和容量等于正常值。

随着积水增加，速度和容量不得增加。

中断道路必须从可通行路网中排除。

检查速度、长度、时间、流量和容量单位是否一致。

# Phase 06：用户均衡交通流分配

## 任务

实现完整的BPR道路阻抗函数和Frank-Wolfe用户均衡交通分配算法。

道路阻抗：

`t_e(x) = t_e0 × [1 + alpha × (x_e/c_e)^beta]`

默认参数alpha=0.15，beta=4。

实现步骤：

1. 初始化可行交通流量。
2. 根据当前流量更新道路阻抗。
3. 按OD需求进行全有或全无交通分配。
4. 计算Frank-Wolfe搜索方向。
5. 使用一维线搜索计算步长。
6. 更新道路流量。
7. 计算相对间隙Relative Gap。
8. 判断是否收敛。

优先在Sioux Falls路网上验证正确性，再运行深圳路网。

必须保留平行道路的独立属性与流量，不能错误合并MultiDiGraph中的道路边。

对于灾害导致不可达的OD，独立记录未满足出行需求。

不能直接删除不可达OD后声称整体出行时间下降。

静态Frank-Wolfe求解的是各时间片的用户均衡，不能称为完整的动态交通分配模型。跨时间片排队和车辆滞留主要由后续SUMO仿真体现。

使用按起点聚合的最短路径计算、缓存、稀疏OD和并行化提高求解效率。

## 输出

- traffic_assignment.py
- frank_wolfe.py
- link_flows.csv
- traffic_congestion_map.png
- relative_gap_curve.png
- travel_time_statistics.csv
- unserved_od.csv
- Sioux Falls验证报告

## 验收条件

OD需求满足量与未满足量之和等于原始OD需求。

道路节点流量守恒误差满足设定阈值。

Sioux Falls的交通分配结果应与可靠参考实现或公开基准进行比较。

建议Relative Gap达到1e-4；未达到时必须报告实际收敛情况。

# Phase 07：交通网络韧性评价

## 任务

实现三种韧性指标。

### 结构韧性

- 最大连通子图节点比例。
- 强连通性及弱连通性。
- 网络效率。
- 道路可用比例。

不可达节点对的网络效率贡献记为0。

道路网络效率需要明确使用纯拓扑距离还是通行时间加权距离。

### 性能韧性

- 系统总出行时间。
- 平均出行时间。
- 交通拥堵比例。
- 未满足OD需求比例。

将总出行成本定义为：

`C(t) = sum(x_e × t_e) + rho × D_unserved`

惩罚系数rho需要进行敏感性分析，防止模型通过取消出行获得更好的评价。

使用相同时间片、相同OD需求下的无灾害基准作为归一化依据。

### 功能韧性

计算居民到最近医院、消防站和避难所的网络出行时间。

计算能够在15分钟和30分钟内到达应急设施的人口比例。

如果没有真实人口数据，则明确指标为交通小区覆盖比例或合成人口覆盖比例。

### 综合韧性

`Q(t) = ws × Qs(t) + wp × Qp(t) + wf × Qf(t)`

默认权重：

- ws = 0.2
- wp = 0.5
- wf = 0.3

综合韧性：

`R = integral(Q(t), t=0...T) / T`

使用数值积分计算韧性曲线面积。

保证不同策略使用相同的时间窗口、基准、权重及交通需求。

## 输出

- resilience.py
- accessibility.py
- resilience_timeseries.csv
- resilience_curve.png
- hospital_accessibility_map.png
- resilience_summary.csv

## 验收条件

正常情景下归一化指标应接近1。

完全中断的测试路网应表现出合理的功能损失。

指标处理不得出现除零、NaN或无说明的无限值。

# Phase 08：关键积水道路识别

## 任务

研究积水道路对整体交通系统的影响。

分别计算：

1. 道路峰值积水深度。
2. 正常交通流量。
3. 道路介数中心性。
4. 道路失效导致的网络性能损失。
5. 道路失效导致的医院可达性损失。
6. 治理该道路带来的综合韧性提升。

对每个候选积水道路，模拟单独治理后重新进行交通分配及韧性评价。

定义：

`Delta_R_e = R_after_e - R_before`

建立道路边际贡献排名。

分析：

- 积水最深的道路是否也是最关键的道路。
- 流量最高的道路是否最值得治理。
- 哪些道路具有较强的网络替代作用。

通过排名相关性和空间分布比较不同重要性指标。

## 输出

- road_criticality.py
- critical_road_ranking.csv
- critical_roads.geojson
- critical_roads_map.png
- importance_correlation.png

## 验收条件

关键道路排名必须来自实际模型计算。

不得预设某条道路一定最重要。

# Phase 09：有限预算下的道路治理策略优化

## 任务

将灾前排水能力改造作为主研究对象。

设二元决策变量x_e表示是否治理道路e。

治理后积水深度：

`h_new_e(t) = h_e(t) × (1 - delta_e × x_e)`

初期使用统一的治理成本与治理效果，后续增加道路差异化成本及治理效果。

建立优化模型：

目标函数：

`maximize sum(p_omega × R_omega(x))`

约束条件：

`sum(cost_e × x_e) <= Budget`

`sum(x_e) <= K`

`x_e ∈ {0, 1}`

如果缺乏真实灾害概率，使用明确标注的等权情景，不将其称为真实概率估计。

实现以下算法：

- No Intervention：不治理。
- Random：随机治理。
- Depth-first：积水深度优先。
- Flow-first：正常交通流量优先。
- Centrality-first：介数中心性优先。
- Resilience-Greedy：单位成本韧性收益优先。
- Genetic Algorithm：遗传算法，可作为进一步对照。

韧性贪心算法步骤：

1. 初始化已治理道路集合为空。
2. 枚举预算允许的未治理候选道路。
3. 模拟增加治理该道路后的积水变化。
4. 重新进行交通分配。
5. 重新计算综合韧性。
6. 计算单位成本韧性增益。
7. 选择收益最大的可行道路。
8. 更新已治理集合及剩余预算。
9. 重复计算，直到无法继续治理。

在小型路网中使用穷举搜索验证最优解，并计算贪心算法与最优解的差距。

大型路网使用候选道路筛选、并行计算和结果缓存提高效率。

如果贪心算法未超过某些基准方法，如实记录，不得修改结果以制造性能优势。

## 输出

- optimization/
- optimized_road_selection.csv
- budget_allocation.csv
- optimized_roads_map.png
- strategy_comparison.csv
- optimization_runtime.csv

## 验收条件

任何治理方案都不能超过预算限制。

相同预算下比较各个策略。

所有声称的韧性收益必须通过重新计算验证。

# Phase 10：SUMO微观交通仿真

## 任务

将真实OSM路网转换为SUMO网络。

首先选择小规模区域验证，再扩展到南山区中计算资源能够承受的规模。

完成：

1. OSM至SUMO路网转换。
2. 建立OSM道路边与SUMO edge ID对应关系。
3. 根据OD矩阵生成车辆及出发时间。
4. 生成初始车辆行驶路线。
5. 通过TraCI动态更新道路速度。
6. 根据内涝状态设置道路通行限制。
7. 实现车辆重新路径规划。
8. 模拟积水增长及道路恢复。
9. 统计车辆排队、等待、出行时间和未完成出行。

需要注意：

SUMO道路容量不能直接等同于BPR容量参数，应通过速度、车道限制、跟驰行为等机制进行校准或近似实现。

道路中断时，应合理处理已经位于该路段上的车辆，避免直接删除车辆制造虚假改善。

比较三个主要情景：

- 正常交通。
